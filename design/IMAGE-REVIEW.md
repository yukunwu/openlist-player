## 文件库 · Sunburst

图：`generated/file-library-sunburst-v1.png`

- 值得保留：深青灰底、暖金文件夹、薄荷聚焦框，以及文件名 / 次要元信息 / 右侧大小的层级；没有假海报，选项也采用行附近的两项菜单，整体方向正确。
- 不可照抄：模型把导航擅改为“文件 / 图片 / 视频 / 音乐 / 文档 / 设置”。产品应保留“文件库 / 上一级 / 刷新 / 服务器”，不能为画面增加分类功能。
- 版式偏差：侧栏约占图宽 11%，折算 960dp 约 105dp，比约定 84dp 宽；标题也明显大于 20sp。回收这两处空间，保持紧凑两行标题。文件夹图标比规格更大、更粗，可减至 24dp 细线。
- 元信息全部是合成示例：子项数、日期、大小、分辨率均不能当成服务器已提供或实际解析结果。尤其文件库不得仅凭扩展名显示 `1920 × 1080`；目录子项数未知时不显示。
- 局部背景可见不均匀暗斑，不应制作成纹理资产；Android 用平滑轻渐变。菜单小三角与底部多组提示也非必需，优先简化，避免重复“菜单 / 选项”文案。

## 播放器 · Flare

图：`generated/player-flare-v1.png`

- 更接近目标：顶部确实只有两行媒体信息；画面占绝大多数面积；底部文字动作、细进度条和透明亮度细轨均值得采用。比例菜单把当前值勾选与另一个选项的焦点高亮分开，状态区分正确。
- 不可按像素照抄：菜单在图中偏窄、项高不足 TV 48dp 目标；菜单应锚定“原始”按钮，而不是让三角尖看似指向进度条。播放暂停的圆圈不是必要装饰，可换成无实底 48dp 焦点触点。
- 时间与进度为示意且不完全一致：`00:38 / 03:24` 约 19%，绘制填充约 20%；实际 UI 必须由同一播放状态计算，不读取生成图文案。
- 场景是模型生成的合成海岸，不是真实影片截图，也不是建议新增的联网背景。顶部 H.264 / 帧率 / AAC 同样只是样例，实际只显示播放轨道确认的数据。
- 图中缺少手机锁定入口与亮度百分比；实际触摸界面在控制层显示时提供左侧锁图标，HUD 补小号数值。图同时呈现亮度 HUD 和比例菜单只是元素展示，不能当作常态：菜单优先接收输入，调节 HUD 短暂出现后自动消失，不在菜单打开时继续识别底层手势。
- 这张静态图不能证明菜单按键隔离、亮度长按门槛、右侧音量滑动、自动隐藏或锁定。它也没展示“仅解锁可用”的锁定态；锁定态按规格独立实现。

## 推荐

以 Flare 播放器图作为视觉气质主参考，以 Sunburst 文件页的行层级与配色作为辅参考；不直接照搬任一图的导航、尺寸和数据。实现优先级是：84dp 窄轨与紧凑标题 → 去厚重按钮 → 细焦点及锚定菜单 → 短暂透明 HUD。保留当前功能边界，真实交互继续以离线预览和状态机规格对照，最终用手机与 TV 分别验证。

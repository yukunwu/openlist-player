## 0.1.9 修复结果

- 请求头语义：删除错误的 fs/get.header 解析；核对上游 `/api/fs/link` 需要 AuthAdmin，不增加管理员登录要求。带头源由 OpenList 原有 Web Proxy 处理，直链策略不变；不声称新增了客户端任意驱动请求头支持。
- 配对超时：独立绝对期限定时器关闭监听与活动 socket，覆盖阻塞读/写，手动关闭取消定时器；新增慢速头、未完成请求体、阻塞响应和主动关闭回归测试。
- 音频：配置 MEDIA/MOVIE 音频属性、Media3 焦点处理及 audio-becoming-noisy 暂停；实际来电、焦点抢占与耳机断开仍需手机验证。
- Range：206 校验 Content-Range 起点、区间、总长度和 Content-Length；416 只有精确 EOF 可成功，其他状态报错；保留源忽略 Range 时顺序跳过兼容，未人为新增大文件限制。
- 依赖：注册表最新仍是 node-forge 1.4.0，不虚构升级版本。构建只包含 AES/cipher/util 等所需模块，去除 RSA/ASN.1/PKI 和 Forge 随机数实现；随机 IV 使用浏览器 getRandomValues。源码依赖仍会被版本扫描命中，运行时不包含公告所述代码。
- 配色：配对网页同步中性黑灰、白色焦点和红色按钮，真实 Chrome 提交合成数据至 Java 解密通过；未添加任何第三方资源。
- 未添加 CI 门禁、发布审批或新权限；没有改动用户服务端配置、登录 token 保存方式或现有会话。

## 初次发现（历史记录）

1. **P1 / 云盘兼容：媒体请求头来源错误。** `MainActivity.java:412` 将 `/api/fs/get.header` 当成
   JSONObject。核对上游 `server/handles/fsread.go`，该值实际是元数据页面头部字符串，而非驱动
   `Link.Header`。需要 Cookie/Referer/UA 的源会丢失必要参数，可能 403 或不可播。应核实可用链接接口
   及权限，正确处理驱动头或明确使用服务端代理，补协议集成测试；不能靠解析页面字符串“修复”。
2. **P2 / 安全与生命周期：扫码连接可绕过绝对超时。** `PairingServer.java:58` 只有单次读取超时，
   `PairingServer.java:75` 的读循环不检查绝对期限；`PairingServer.java:135` 只关闭监听 socket，
   没有关闭已接受连接。局域网慢速发送者可占住串行处理线程，延长到期/离开后的连接存活。
   本机合成探针以 100ms TTL、每 100ms 一个字节复现：600ms 后仍未触发到期，close 后处理线程仍存活。
   应加入绝对截止时间、跟踪并关闭活动 socket、处理输出阻塞，并覆盖慢速头/体与离开页面测试。
   未发现此问题可绕过 GCM 验证或直接取得密码；主要是拒绝服务和关闭语义缺失。
3. **P2 / 手机音频行为：未申请播放器音频焦点。** `PlayerActivity.java:368` 创建 ExoPlayer 后
   未配置 `setAudioAttributes(..., true)` 或自行管理焦点，也未启用拔耳机暂停。通知、导航播报、其他
   音频 App 请求焦点时，本应用不能按预期自动暂停/降低音量，拔耳机可能转扬声器。应明确媒体音频属性
   并测试焦点丢失、恢复、来电和耳机断开。
4. **P2 / 播放协议：206 响应缺少 Content-Range 校验。** `MediaHttpDataSource.java:77` 接受任意
   2xx，`MediaHttpDataSource.java:83` 对非 200 不校验起始偏移。代理返回错误偏移时，播放器收到的是
   错误位置字节，可能解析失败或 seek 错位。应验证 206 起点/长度、区分 416/文件末尾，并测试源忽略 Range
   时的大偏移策略。目前 HTTP 数据源没有针对这些行为的集成测试。
5. **P2 / 依赖风险：node-forge 1.4.0 存在已知 RSA 公告。** OSV 返回
   `GHSA-86w9-cpqp-85rv`（RSA PKCS#1 v1.5 嵌套 DigestAlgorithm 验证缺陷）。当前配对代码使用随机数和
   AES-GCM，没有发现调用 RSA 验签的路径，因此不能宣称已证实可利用。但打包完整受影响库仍需跟踪公告、
   升级至经核验的修复版本或缩减为所需模块，保留许可证并重跑真实浏览器加解密测试。
6. **P3 / UI 一致性：配对网页仍使用旧配色。** `app/src/main/assets/pairing.html:7` 仍是深蓝绿背景
   和橙色按钮，与已选定的中性黑灰半透明/白焦点/红点缀不一致。现有色板测试只覆盖 Java 常量，未覆盖网页。

## 已确认的保护与限制

- 默认服务器已移除；账号/密码不内置，登录字段为空，已有认证会话保留。
- OpenList 令牌按源绑定、Keystore AES-GCM 保存；备份/迁移关闭，密码不写入偏好。
- 登录与配对窗口禁止截图；Player/Pairing Activity 不对外导出。
- HTTPS 没有忽略证书校验；API 禁止重定向，媒体跨源不附带原源额外头；尚缺端到端媒体重定向安全测试。
- 配对采用一次性 GCM、Origin/Host/长度校验，但表单本身经 LAN HTTP 提供，不防主动中间人；界面已披露。
- 明文 HTTP 对所有显式配置地址开放，并非代码强制“仅局域网”；只能推荐 HTTPS，不能声称强制安全传输。
